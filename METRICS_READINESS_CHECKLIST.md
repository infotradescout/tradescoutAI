# Metrics Readiness Checklist

**Purpose**: Verify each proof module metric can be shown without inventing data

## Verification Criteria (All Must Pass)

Before showing any metric in the "Live Proof Snapshot", verify it meets ALL criteria:

1. ✅ **Queryable** — Can be retrieved from existing tables/logs without schema changes
2. ✅ **Time-bounded** — Has clear date range (7d/30d) and can filter accurately
3. ✅ **Counts-only** — Returns aggregate counts, not individual records
4. ✅ **Non-identifying** — Contains no PII (names, emails, phone, addresses)
5. ✅ **Performant** — Query executes in <500ms on production dataset
6. ✅ **Accurate** — Metric definition matches user-facing claim
7. ✅ **Stable** — Not dependent on features still in development

**If ANY criterion fails → OMIT the metric entirely (no zeros, no placeholders).**

## Metric 1: Decision Cards Processed (Last 7 Days)

**Definition**: Count of decision cards generated by Scout in the last 7 days.

**Query Source**:
- [ ] Table exists: `decision_cards` or equivalent
- [ ] Has `created_at` timestamp
- [ ] Can filter by `created_at >= NOW() - INTERVAL '7 days'`

**Verification Steps**:
1. [ ] Run query against production-like data
2. [ ] Verify count is non-zero and reasonable (not 0, not millions)
3. [ ] Confirm no PII in aggregation
4. [ ] Test query performance (<500ms)

**SQL Template** (example):
```sql
SELECT COUNT(*) 
FROM decision_cards 
WHERE created_at >= NOW() - INTERVAL '7 days';
```


## Metric 3: Active Counties

**Definition**: Count of counties with at least 1 verified professional or active decision card in last 30 days.

**Query Source**:
- [ ] Table exists: `county_entities` or `users` with `county_id`
- [ ] Can join to verification status or decision card activity
- [ ] County field is populated and accurate

**Verification Steps**:
1. [ ] Run query against production-like data
2. [ ] Verify count reflects real activity (not just signup geography)
3. [ ] Confirm definition matches "active" claim
4. [ ] Test query performance (<500ms)

**SQL Template** (example):
```sql
SELECT COUNT(DISTINCT county_id)
FROM users u
WHERE u.verification_status = 'verified'
  AND u.county_id IS NOT NULL;
```

**Status**: [ ] Ready / [ ] Not Ready / [ ] Omit

## Metric 4: Median Time-to-Decision (Optional)

**Definition**: Median time from initial Scout interaction to Decision Card generation.

**Query Source**:
- [ ] Tables track: Scout session start + Decision Card creation
- [ ] Can calculate time delta
- [ ] Has enough data for meaningful median (n ≥ 20)

**Verification Steps**:
1. [ ] Run query against production-like data
2. [ ] Verify median is reasonable (not 0s, not hours)
3. [ ] Confirm calculation accuracy
4. [ ] Test query performance (<500ms)

**SQL Template** (example):
```sql
SELECT PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY time_to_decision)
FROM (
  SELECT EXTRACT(EPOCH FROM (dc.created_at - s.started_at)) / 60 AS time_to_decision
  FROM decision_cards dc
  JOIN scout_sessions s ON dc.session_id = s.id
  WHERE dc.created_at >= NOW() - INTERVAL '30 days'
) AS times;
```

**Status**: [ ] Ready / [ ] Not Ready / [ ] Omit

**Default**: If not ready → OMIT (do not show 0 or "N/A")

```typescript
  .filter(([_, value]) => value !== null && value > 0)
  .map(([key, value]) => ({ key, value }));

// If no valid metrics, hide entire module

  return null; // Do not render proof module
}

// Otherwise, render only valid metrics
return <ProofSnapshot metrics={validMetrics} />;
```

## Fail-Safe Rules

1. **Never show zero** — If count = 0, omit metric entirely
2. **Never show placeholder** — No "Coming soon", "N/A", or "—"
3. **Never invent data** — No hardcoded counts, no fake numbers
4. **Never leak PII** — All queries must be aggregates only
5. **Hide on failure** — If any query errors, hide entire proof module (log error silently)
