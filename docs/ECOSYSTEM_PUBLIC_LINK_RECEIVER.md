# Source-approved public navigation on canonical TradeScout profiles

The existing canonical Profile is the TradeScout identity. This slice stores only qualified public reference pointers in its existing `custom` content block: app, opaque public partition and source ID. It creates no profile database, account, membership, entitlement, owner mapping, county assignment or paid service. Native profile ownership and stale-edit/target conflict protection still use the existing ProfileSiteEditor and profile PUT/CAS flow. Native public exposure still uses `storage.getProfileBySlugPublic`, including its current trust and target-authority checks.

A profile owner can add a MealScout sharing link in the existing editor and save it with the rest of the profile. A visitor can click Open MealScout profile from that canonical TradeScout page. The existing public profile remains independently readable; the additional API verifies that the requested reference belongs to that currently public profile, fetches only the actual MealScout source-approved envelope, rereads the native profile identity/reference binding, and returns a short-lived public navigation reference. The browser immediately opens the original MealScout canonical. No signup or cross-product cookie/token is needed for this public navigation. Source withdrawal, quarantine, changed native ownership/content, missing approval, private target, invalid fields, expiry or outage makes the next open unavailable. The underlying TradeScout page and gated DirectConnect controls stay available.

No name/link payload is stored or polled. The UI's neutral configured link control persists as profile navigation metadata; it does not display a cached publisher name or carry an old authorization. Every click revalidates. This avoids indefinite stale cards and background polling against the source's one-second reference lifetime and existing60/minute source limiter. The source limiter is shared by the receiver's egress identity; popular usage can throttle optional opens. No cost or availability claim is made. Publisher and receiver retain their own deploy/database/failure boundaries; optional requests still share each product's native database pools.

## Source and transport contract

Only the existing MealScout service origin `https://mealscout.onrender.com` can supply this first adapter. HTTP redirects are rejected, credentials omitted and JSON body bounded4KB/256chunks. The receiver's response wait is bounded750ms and aborts its source HTTP fetch on expiry; the existing native profile DB reader does not accept a cancellation signal, so already-started DB work can outlive the response. No native query timeout, cancellation, DB-work/cost cap or guaranteed availability is introduced. The source's approved reference must expire within one second; native revalidation and browser navigation also reject a late response. A valid issued reference can remain usable until that subsecond expiry if the source withdraws after its authority read; this is not atomic instantaneous revocation through navigation. Unknown/private envelope fields fail closed. A client-supplied approved flag, account, URL, role or owner ID has no authority. No route accepts an arbitrary origin or returns private customer data. The browser checks this public receiver API on the page's own origin, including a mapped custom domain, preserving native CORS instead of broadening its allowlist. There is no new CORS, cookie, CSRF exemption, credential or security setting. Browser query/HTTP flags do not create cross-app authority.

Existing content block form:

```json
{"type":"custom","data":{"kind":"ecosystemPublicLinks","references":[{"app":"mealscout","tenantId":"<32 lowercase hex characters>","sourceId":"<native source ID>"}]}}
```

The maximum is three unique references in one block, within200blocks. Native names, addresses, contacts, menus, payments, history and custody remain native. These are public links selected for a page; they make **no same-business, same-owner, verified affiliation or shared-login claim**. Visibility grants no contact or account permission. Source approval does not make a source owner the owner of a TradeScout page; TradeScout page ownership does not approve a source publication.

`TRADESCOUT_ECOSYSTEM_LINKS_ENABLED=false` makes resolution unavailable without a source call. Existing profiles have no such block, so default-on capability makes zero source calls until a native owner deliberately configures one and a visitor clicks. Revert additive code to roll back; keep native profile content/history. Removing a pointer on one profile is a normal native owner edit, not revocation of the source's grant.

## Remaining identity decision

Before shared login/account actions, choose an explicit dual-authentication account-link contract: which existing authority issues an app-scoped identity, what the two signed-in owners consent to, and how either product revokes that link.
