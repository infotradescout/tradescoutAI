# Scout Internal Data API (SIDA) - Internal Documentation

**Version**: 1.0
**Status**: Production Ready
**Last Updated**: February 21, 2026

## 1. Overview

The Scout Internal Data API (SIDA) is a secure, internal-only gateway that exposes the rich "byproduct data" generated by the TradeScout platform. It allows other internal projects to leverage Scout's reasoning and data factory for cross-platform analysis and actions.

**Base URL**: `/api/scout-internal-data`

## 2. Authentication

All SIDA endpoints require secure authentication. Requests must include the following headers:

| Header | Description | Example |
| :--- | :--- | :--- |
| `X-Scout-API-Key` | Your project's unique API key (from environment variables) | `your_project_api_key` |
| `X-Scout-Project-ID` | Your project's unique identifier | `my_internal_project` |
| `X-Scout-Timestamp` | Current Unix timestamp (in milliseconds) | `1677000000000` |
| `X-Scout-Signature` | HMAC-SHA256 signature of the request payload | `your_generated_signature` |

### Signature Generation

The signature is a HMAC-SHA256 hash of the project ID, timestamp, and request payload, signed with your internal API key.

**Example (Node.js):**
```javascript
const crypto = require('crypto');

const internalApiKey = process.env.SCOUT_INTERNAL_API_KEY;
const projectId = 'my_internal_project';
const timestamp = Date.now();
const payload = { /* your request body */ };

const message = `${projectId}:${timestamp}:${JSON.stringify(payload)}`;

const signature = crypto
  .createHmac('sha256', internalApiKey)
  .update(message)
  .digest('hex');
```

## 3. Endpoints

### 3.1. Status

Check the status and configuration of the SIDA.

- **Endpoint**: `GET /status`
- **Success Response (200)**:
```json
{
  "success": true,
  "data": {
    "configured": true,
    "allowed_projects": ["my_internal_project"],
    "request_timeout_ms": 30000
  },
  "metadata": { ... }
}
```

### 3.2. Data Factory

Access the rich byproduct data generated by TradeScout.

#### Get Marketplace Byproducts
- **Endpoint**: `GET /data-factory/marketplace`
- **Description**: Retrieve trending items, category insights, and market health for the marketplace.

#### Get Contractor Byproducts
- **Endpoint**: `GET /data-factory/contractors`
- **Description**: Retrieve trade demand, contractor insights, and market health for the contractor ecosystem.

#### Get Community Byproducts
- **Endpoint**: `GET /data-factory/community`
- **Description**: Retrieve trending topics, neighborhood insights, and community health.

#### Get All Byproducts
- **Endpoint**: `GET /data-factory/all`
- **Description**: Retrieve a comprehensive dump of all byproduct data.

### 3.3. Reasoning-as-a-Service (RaaS)

Send raw data to Scout and get back intelligent analysis and recommendations.

- **Endpoint**: `POST /reasoning`
- **Request Body**:
```json
{
  "analysis_type": "trend_analysis" | "opportunity_detection" | "risk_assessment",
  "data": { /* your raw data */ },
  "context": { /* optional context */ }
}
```
- **Success Response (200)**:
```json
{
  "success": true,
  "data": {
    "analysis_type": "trend_analysis",
    "findings": [
      "Roofing materials showing 15% price increase over 30 days"
    ],
    "confidence": 0.92,
    "recommendation": "Consider increasing inventory of roofing materials"
  },
  "metadata": { ... }
}
```

### 3.4. Cross-Project Actions

Trigger TradeScout workflows from other internal applications.

- **Endpoint**: `POST /actions`
- **Request Body**:
```json
{
  "action": "vet_contractor" | "calculate_market_value" | "send_notification",
  "parameters": { /* action-specific parameters */ }
}
```
- **Success Response (200)**:
```json
{
  "success": true,
  "data": {
    "action": "vet_contractor",
    "contractor_id": "c_001",
    "status": "vetting_in_progress"
  },
  "metadata": { ... }
}
```

## 4. Environment Variables

To enable SIDA, you must set the following environment variables:

- `SCOUT_INTERNAL_API_KEY`: Your secret API key for signing requests.
- `SCOUT_ALLOWED_PROJECTS`: A comma-separated list of project IDs that are allowed to access SIDA.

## 5. Security

- **Internal Use Only**: This API is not intended for public use.
- **Request Signing**: The HMAC-SHA256 signature ensures that requests are authentic and have not been tampered with.
- **Timestamp Validation**: The timestamp prevents replay attacks.
- **Project Whitelist**: Only authorized projects can access the API.

## 6. Example Usage (cURL)

```bash
# Generate signature (example)
SIGNATURE=$(node -e "const crypto = require('crypto'); const message = 'my_internal_project:1677000000000:{}'; const signature = crypto.createHmac('sha256', 'your_secret_key').update(message).digest('hex'); console.log(signature);");

# Make API request
curl -X GET \
  -H "X-Scout-API-Key: your_secret_key" \
  -H "X-Scout-Project-ID: my_internal_project" \
  -H "X-Scout-Timestamp: 1677000000000" \
  -H "X-Scout-Signature: $SIGNATURE" \
  http://localhost:3000/api/scout-internal-data/status
```
