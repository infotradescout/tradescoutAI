# System Prompt Loading + Hot Reload - Complete Implementation

## Overview

The system now has full support for loading, editing, and hot-reloading the AI assistant's system prompt without restarting the server. The system enforces a strict 4-layer knowledge hierarchy: Admin Cache → Local Data → Internet → Honest Unknown.

## Backend Implementation

### 1. Prompt Service (`server/services/promptService.ts`)

**Purpose**: Manages system prompt loading with caching and hot reload

**Key Features**:
- Loads prompt from `server/cache/manual/system_prompt.md` at startup
- Caches for 30 seconds for performance
- Force reload capability for admin edits
- Status tracking (cached, lastLoaded, exists)

**Functions**:
```typescript
loadSystemPrompt(force = false): string
reloadSystemPrompt(): string
getPromptStatus(): PromptStatus
```

**How It Works**:
1. First request loads from disk and caches
2. Subsequent requests within 30s use cache
3. After 30s, automatically reloads from disk
4. Admin edits trigger force reload immediately

### 2. Prompt Admin Route (`server/routes/promptAdmin.ts`)

**Purpose**: Admin endpoints for prompt management

**Endpoints**:

- **GET `/api/prompt-admin`** - Retrieve current prompt
  - Response: `{ content, status, message }`
  - Requires: super_admin or head_admin role

- **POST `/api/prompt-admin`** - Update and reload prompt
  - Request: `{ content: string }`
  - Response: `{ ok, message, updatedBy, timestamp }`
  - Hot-reloads immediately for new conversations
  - Requires: super_admin or head_admin role

- **GET `/api/prompt-admin/status`** - Get loading status
  - Response: `{ status }`

- **POST `/api/prompt-admin/reload`** - Force reload from disk
  - Response: `{ ok, message, reloadedBy, timestamp }`

**Authorization**: All endpoints require `super_admin` or `head_admin` role

## Knowledge Hierarchy Implementation

### 4-Layer Resolution

```
Layer 1: Admin Manual Cache (HIGHEST PRIORITY)
├─ Files in /server/cache/manual/
├─ Override all other sources
└─ Used exactly as written

Layer 2: Website Data (LOCAL FIRST)
├─ Auto-generated cache /server/cache/autogenerated/
├─ Live database queries
└─ Real data from platform

Layer 3: Internet Search (WITH ATTRIBUTION)
├─ Only when layers 1 & 2 empty
├─ Clearly labeled "based on wider web"
└─ No local data fabrication

Layer 4: Honest Unknown (FINAL FALLBACK)
├─ No data found anywhere
├─ Honest "I don't know" response
└─ Suggest next steps
```

### Hyperlocal Priority

```
County → State → Region → National
```

When falling back, always inform user:
> "I don't have specific roof repair data for Harris County, so here's statewide guidance for Texas."

### System Prompt Rules Enforced

From `server/cache/manual/system_prompt.md`:

✅ DO:
- Use admin cache when available
- Query local database for real data
- Search internet only when necessary
- Clearly attribute sources
- Say honestly when data unavailable

❌ DON'T:
- Invent contractor details, prices, or companies
- Fabricate HOA rules or regulations
- Create example/placeholder data
- Mix sources (don't present web data as local)
- Return mock data anywhere

## Workflows

### Updating System Prompt

1. **Admin opens** `/admin/system-prompt` page
2. **Admin edits** the Markdown prompt in the textarea
3. **Admin clicks** "Save Prompt" button
4. **Backend**:
   - Validates content (not empty)
   - Writes to `server/cache/manual/system_prompt.md`
   - Force reloads cache immediately
   - Logs update with admin ID
5. **Frontend**: Shows success message, keeps editor open
6. **New conversations** immediately use updated prompt
7. **Existing conversations** keep original context

### Hot Reload Timeline

```
T=0s:     Admin saves prompt
T=0s:     Backend writes to disk
T=0s:     Cache force reloaded
T=0.5s:   Frontend shows "saved" message

T=1s:     New user conversation starts
T=1s:     loadSystemPrompt() called
T=1s:     Cache valid (within 30s reload window)
T=1s:     Returns updated prompt
T=1s:     Gemini receives new rules
T=1s:     New conversation uses updated behavior

T=35s:    Prompt cache expires
T=35s:    Next loadSystemPrompt() call
T=35s:    Reloads from disk
T=35s:    Gets any updates made in interim
```

### Fallback Scenarios

```
✓ DATABASE_URL missing
  ❌ System fails fast with clear error
  ❌ No mock fallback

✓ system_prompt.md missing
  ❌ promptService throws error at startup
  ❌ Clear error message with path

✓ Admin cache empty for query
  ✓ Falls through to local database
  ✓ Returns real data if found
  ✓ Continues to internet if empty

✓ No data found anywhere
  ✓ Returns honest "I don't know"
  ✓ Suggests next steps to user
  ✓ No fabricated data
```

```typescript
async function handleAssistantMessage(message: string, user: User) {
  // 1. Load current system prompt (hot-reload aware)
  const systemPrompt = loadSystemPrompt();

  // 2. Resolve knowledge using 4-layer hierarchy

  // 3. Send to Gemini with prompt + knowledge

    { role: "system", parts: [{ text: systemPrompt }] },
    {
      role: "user",
      parts: [
        { text: JSON.stringify({ message, user, knowledge }) }
      ],
    },
  ]);

  // 4. Parse and execute actions
  const parsed = JSON.parse(response.text());
  return await runAssistantActions(req, user, parsed.actions);
}
```
