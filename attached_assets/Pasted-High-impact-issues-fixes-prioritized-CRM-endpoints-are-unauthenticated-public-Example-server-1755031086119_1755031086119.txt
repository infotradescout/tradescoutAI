High‑impact issues & fixes (prioritized)
CRM endpoints are unauthenticated (public)

Example: server/crm-routes.ts registers /api/crm/... without isAuthenticated.

Risk: exposure of contact/deal/lead data.

Fix (minimal):

ts
Copy
Edit
// server/crm-routes.ts
import { isAuthenticated } from "./auth";
export function registerCrmRoutes(app: Express) {
  app.use("/api/crm", isAuthenticated as any);
  // ...existing routes remain the same
}
Or wrap each route individually with isAuthenticated (and roles where needed).

No baseline HTTP hardening

Missing helmet, CORS policy, and rate‑limiting.

Fix (server/index.ts):

ts
Copy
Edit
import helmet from "helmet";
import cors from "cors";
import rateLimit from "express-rate-limit";

app.set("trust proxy", 1);
app.use(helmet()); // content security, frameguard, etc.
app.use(cors({ origin: ["https://your-domain.com"], credentials: true }));
app.use(rateLimit({ windowMs: 15*60*1000, max: 300 }));
Add sameSite: "lax" to session cookie, keep secure: true in prod.

WebSocket auth is “allow all” (/ws)

Fix: require a session or signed token on connection, validate user, and reject otherwise.

Payments disabled unless Stripe envs exist

Code checks STRIPE_SECRET_KEY before initializing. Add keys when you’re ready or hide pay UI until present.

Object storage uses Replit sidecar; if you’re deploying elsewhere, configure Google Cloud Storage (service account) or swap to S3. Env flags like PRIVATE_OBJECT_DIR / PUBLIC_OBJECT_SEARCH_PATHS exist.

Missing pages / broken links

See MISSING_PAGES_REPORT.md in repo for exact route mismatches to fix quickly.
