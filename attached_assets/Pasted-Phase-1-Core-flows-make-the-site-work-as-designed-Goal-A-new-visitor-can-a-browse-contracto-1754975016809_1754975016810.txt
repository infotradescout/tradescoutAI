Phase 1 — Core flows (make the site “work as designed”)
Goal: A new visitor can (a) browse contractors, (b) filter by location/trade, (c) request a quote, and (d) you can see submissions in admin. Contractors can (e) apply/join. Your team can (f) approve/verify.

4) Quote Request flow (the money path)
Form fields you asked for:

Service (qs_service): Painting / Roofing / Flooring (extensible)

Square Footage (qs_sqft): number, placeholder 1500

Contact info: name, email, phone, address (required on “Request Exact Quote”)

Business rule: Calculator is optional, but if used, include its numbers in the payload when the form submits.

Submit payload example:

  "contact": { "name":"...", "email":"...", "phone":"...", "address":"..." },
  "source": "web",
  "utm": { "campaign":"...", "ad":"..." }

Show success state + send a confirmation email (server) + log to CRM/DB.

5) Contractor signup & verification
Minimal fields: business name, trade categories, service area (counties), insurance doc upload, references.

Statuses: pending_review → approved → featured (optional).

Admin screen: approve/deny, attach notes, set “recommended score.”

6) Admin inbox
A single Submissions page (protected route) listing:

Quote Requests

Contractor Applications

Filters: date range, trade, county, status. Export CSV button.

✅ Acceptance check: I can: browse board → filter → open contractor → request quote → see it in Admin; contractor can apply → you can approve → they appear on board.

Phase 2 — Polish & growth
SEO & social

Per‑route <title>, <meta name="description">, and schema.org JSON‑LD for LocalBusiness/Service.

OpenGraph/Twitter tags on contractor profiles and the board landing.

Analytics + events

Add basic pageview + custom events: quote_request_started, quote_request_submitted, contractor_application_submitted.

Error reporting

Add Sentry (or similar) with beforeSend scrubbers. Wire your ErrorBoundary to capture + user context (non‑PII).

Performance

Vite chunking (vendor split), react lazy routes where appropriate, image lazy‑loading, and audit bundle size.

Accessibility

Keyboard‑navigable DnD (hello‑pangea/dnd supports it), focus rings, proper labels/aria for your forms and tabs.
