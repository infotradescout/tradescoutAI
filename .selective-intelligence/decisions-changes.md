# Decisions and Semantic Changes

## Governing invariants

- `DEC-SEPARATE-ROUTE`: JW Stone 2.0 exists only as a separate `/jw-stone` experience; the existing profile is protected unchanged.
- `DEC-TRUTH-ONLY`: canonical explicit source data governs published stone facts and missing facts remain absent.
- `DEC-NO-PRICE`: public price and price-derived surfaces are prohibited.

## Active release commitments

- `DEC-AUDIENCE-LENS`: the four customer paths are optional one-click guidance inside one always-visible storefront. A path changes only sourced knowledge, a compact evidence-linked recommendation rail, and supported fact priority.
- `DEC-LOCAL-WISHLIST`: eligible named-stone IDs persist in a bounded versioned browser-local wishlist without an account or contact gate.
- `DEC-DRAFT-ONLY`: the build stops at an unmerged draft until real desktop and mobile exact-head proof exists.

## Reversible implementation choice

- `DEC-VISUAL-COLOR`: color directions are explicit editorial visual classifications derived from supplied imagery. They are navigation labels, not geological, origin, suitability, availability, or material assertions. The map may be reviewed and changed without altering canonical inventory identity.

## Deferred data decisions

Actual First Cut stone assignments and verified country-of-origin values remain deferred until JW supplies source-authorized facts. Their absence is intentional release behavior, not a reason to fabricate sample production data.

## Semantic change ledger

Release one adds the separate marketplace, immediate catalog presentation, compact customer guidance, optional refinements, placeholders, origin contract, local wishlist, safe contact context, metadata, and protections. It deliberately leaves the current JW profile, custom domain, presentation settings, inventory identities, public pricing posture, Direct Connect submission lifecycle, database schema, production configuration, DNS, and deployment state unchanged.

## Authorized amendment: AMEND-AUDIENCE-LENS

Authority: Thomas's direct August 3 correction as the product owner.

- ADDED: one-click sourced knowledge for each customer path and a compact rail of no more than six real named JW stones chosen through the exact source and item rules in `data-contract.md`.
- MODIFIED: audience and color state are independent optional aids; valid URL state restores without a staged dependency.
- REMOVED: buyer-to-color gating, required questionnaires, full-screen selection stages, four buyer workspaces, path-specific replacement layouts, and inventory withholding.
- RENAMED: the obsolete buyer/workspace concept becomes customer-path guidance or audience lens.
- UNCHANGED: the exact MarketplaceHeader → hero → First Cut → compact guide → Current Inventory → footer manifest, approved JW wording, route separation, canonical truth rules, current profile, wishlist, galleries, deliberate Direct Connect, no-price rule, and draft-only release boundary. Unapproved story, trust, FAQ, recommendation, or sales-copy sections are not added.

Compatibility impact: old safe buyer/color query parameters remain readable as independent optional state. No URL is allowed to restore the rejected gate. Existing named-stone links, wishlist IDs, and the current JW profile retain their contracts.

Proof impact: prior journey, workspace, card, URL, accessibility, metadata-description, and rendered evidence is invalid. Replacement proof must show immediate inventory, one-click stone access, the exact section manifest, compact path guidance below 520 rendered pixels, exact source links, capped validated recommendation slugs with factual reasons, independent refinements and URLs, stable wishlist/contact boundaries, and unchanged protected chrome on desktop and mobile.

Authority: Thomas's existing canonical-truth and no-invented-availability instructions as product owner.

- MODIFIED: definition prose refers to real supplied catalog selections while retaining the approved `Current Inventory` user-facing heading.

Future changes to an invariant or release commitment require an authorized amendment that explicitly records added, modified, removed, renamed, and deliberately unchanged behavior plus compatibility and proof impact.
