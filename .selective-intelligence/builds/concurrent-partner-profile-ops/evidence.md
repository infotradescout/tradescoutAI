# Concurrent partner profile operations — evidence

## Owner correction

Partner intake cannot pause while shared profile infrastructure is rebuilt. New partnerships, existing profile repairs, reusable profile systems, routing, contact management, and production audits must run concurrently.

The governing operating rule is:

> No partner waits for architecture. No architecture waits for a partner.

## Problem observed

Recent partner work repeatedly exposed the same failure classes:

- Company identity combined with distributor identity
- TradeScout management confused with company ownership
- Managed phone and email copied separately into multiple profile implementations
- Source materials confused with physical inventory
- Public actions opening generic TradeScout screens instead of the company experience
- Correct production records scattered across isolated provisioners
- A successful build treated as completion without an operating profile audit
- New partners entering faster than the shared tools could absorb them

## Adopted operating model

### Live profile lane

Each incoming partner can receive an independent business and profile immediately. Company-specific presentation remains allowed and expected.

### Shared operations lane

Every managed or temporarily stewarded profile is registered once with its:

- Company slug and name
- Profile archetype
- Control mode
- Contact mode
- Exposure mode
- Request mode and operating recipient
- Expected primary action
- Expected managed phone, email, and notification inbox
- Source presence and verified relationship note

### Continuous audit lane

The admin portal reads the registry and current production records together. It checks:

- Business and profile existence
- Active and published status
- Ownership consistency
- Verified admin custody when required
- Public versus direct-only discovery state
- Managed phone, email, notification inbox, and marker
- Claim and transfer status
- Primary action wording
- Request recipient readiness

Each profile is classified as Ready, Needs Attention, or Blocked. One unresolved profile does not stop another profile from remaining live or being corrected.

### Final normalization lane

The approved TradeScout-managed public contact is now one shared authority:

- Phone: `(850) 543-0748`
- Email: `contact@thetradescout.com`

ISSA Build, JW Stone, and R.E.D. Graniti retain different ownership and presentation models while consuming the same managed response destination.

The final production bootstrap pass normalizes managed contact only after individual profile provisioners complete. Each profile is corrected in an independent transaction so one malformed partner cannot roll back every other contact correction.

## Deliberate boundaries

- TradeScout management never becomes company ownership unless the owner record explicitly says so.
- A distributor relationship never becomes ownership of the source company.
- A source material never becomes physical inventory without an asset and inventory position.
- Public and direct-only exposure remain different states.
- An unresolved contact remains visible as an operations gap rather than being filled with invented data.
- Company-specific presentation is preserved. The registry governs operating truth, not visual sameness.
- Existing partners stay live while new partners are added and shared tools improve.
