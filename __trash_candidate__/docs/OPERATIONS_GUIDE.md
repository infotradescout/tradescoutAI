## Architecture Overview

### Production Stack
- **Frontend:** React + Vite, served via NGINX
- **Backend:** Node.js + Express + TypeScript, managed by PM2
- **Database:** PostgreSQL 15 (Alpine), persisted volume
- **Reverse Proxy:** NGINX 1.25 (SSL, static files, health checks)
- **Process Manager:** PM2 (cluster mode, zero-downtime reload)
- **LLM Providers:** Gemini (primary), extensible for OpenAI/others

### Deployment Options
1. **Docker Compose (Local/Staging):** `docker-compose up --build -d`
2. **Kubernetes (Production):** See `k8s-deployment.yaml`
3. **Cloud Platforms:** AWS ECS, Google Cloud Run, Azure Container Instances

## Daily Operations

### Monitoring
- **Health:** `curl http://localhost:3000/api/assistant/health`
- **Logs:** `docker-compose logs app`, `docker-compose logs nginx`
- **Metrics:** `docker-compose exec app pm2 monit`
- **Audit:** `cat admin_audit.log`

### Maintenance
- **Restart App:** `docker-compose restart app`
- **Zero-Downtime Reload:** `docker-compose exec app pm2 reload all`
- **Database Backup:** `docker-compose exec db sh scripts/backup_db.sh`
- **Clear Cache:** `docker-compose exec app pm2 exec "rm -rf server/cache/autogenerated/*"`

## Emergency Procedures

### App Crashes
1. Check logs: `docker-compose logs app | tail -100`
2. Check resources: `docker stats`
3. Restart: `docker-compose restart app`
4. Investigate root cause and create issue

### Database Issues
1. Check connectivity: `docker-compose exec db pg_isready`
2. Check logs: `docker-compose logs db`
3. Restore from backup if corrupted: `docker-compose exec -T db psql -U tradescout tradescout < /backups/backup_YYYYMMDD_HHMMSS.sql`

### High Memory/CPU
1. Check which process: `docker stats`
2. Kill task: `docker-compose exec app pm2 kill <process_id>`
3. Investigate code/query inefficiency
4. Scale horizontally if needed

### SSL Certificate Expiration
1. Generate new cert or renew with Let's Encrypt
2. Place in `/ssl/fullchain.pem` and `/ssl/privkey.pem`
3. Restart NGINX: `docker-compose restart nginx`

## Scaling & Performance

### Horizontal Scaling (Multiple Instances)
- Use Kubernetes HPA or Docker Swarm
- Load balancing via NGINX or cloud load balancer
- Shared database and cache volumes

### Caching Strategy
- **Static assets:** CDN (Cloudflare/CloudFront)
- **API responses:** Redis (optional, add to docker-compose)
- **Database queries:** Indexed, use explain plans

### Load Testing
```powershell
docker-compose exec app node scripts/loadtest.js http://localhost:3000/api/assistant/health 50 20
```

## Deployment Workflow

### Pre-Deployment
1. Test locally: `npm run dev` and `npm run test:run`
2. Build and verify: `docker build .`
3. Run smoke test on staging

### Deployment
1. Pull latest code
2. Build image: `docker-compose build`
3. Zero-downtime deploy: `docker-compose up -d` (no `--build` flag if image already built)
4. Verify: Run smoke test

### Post-Deployment
1. Monitor logs for errors
2. Check analytics for anomalies
3. Confirm health endpoints
4. Review audit log for any issues

### Rollback
1. Revert to previous image: `docker-compose down && git checkout <prev-commit> && docker-compose up -d`
2. Run smoke test
3. Investigate issue and create post-mortem

## Security

### Secrets Management
- Store in `/secrets` (Docker) or `.env` (local)
- Rotate regularly (quarterly recommended)
- Never commit to version control
- Use cloud secret manager in production (AWS Secrets Manager, etc.)

### Access Control
- Super-admins only: prompt editing, analytics, audit logs
- Role-based access throughout platform
- API rate limiting (optional, recommended)

### Monitoring & Auditing
- All admin actions logged to `admin_audit.log`
- Review monthly for suspicious activity
- Enable verbose logging in production

## Cost Optimization

### Tips
- Use Alpine Linux base images (smaller, faster)
- Enable CDN caching for static assets (save bandwidth)
- Right-size database and app memory limits
- Use managed services where appropriate (RDS, Cloud SQL, etc.)
