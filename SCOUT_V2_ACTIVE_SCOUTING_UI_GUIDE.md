# Scout 2.0 Active Scouting UI/UX Guide\n\n## Core Concept: Active Scouting, Not Chat\n\n**Scout is not a chatbot.** Scout is an **active intelligence system** that gathers information from multiple sources and delivers **scouting reports**.\n\n### Key Mindset Shift\n\n| Old (Chat) | New (Scouting) |\n|---|---|\n| \"Ask Scout a question\" | \"Send Scout on a scouting mission\" |\n| Input: Question | Input: Scouting Request |\n| Output: Answer | Output: Scouting Report |\n| Tone: Conversational | Tone: Intelligence Report |\n| Interaction: Back-and-forth | Interaction: One-way mission |\n\n---\n\n## UI Components\n\n### 1. Scouting Request Input\n\n**Instead of a \"Message\" input box, use a \"Scouting Request\" input:**\n\n```\n┌─────────────────────────────────────────────┐\n│  🔍 Scout for...                            │\n│  [Scout for building codes, prices, etc.]  │\n│                                             │\n│  [📍 Location: Austin, TX]  [🔍 Scout]    │\n└─────────────────────────────────────────────┘\n```\n\n**Placeholder text examples:**\n- \"Scout for building codes for a deck\"\n- \"Scout for roofing prices in my area\"\n- \"Scout for licensed electricians nearby\"\n- \"Scout for permit requirements\"\n\n### 2. Scouting Report Display\n\n**Instead of a \"Chat Message\", display a \"Scouting Report\":**\n\n```\n┌──────────────────────────────────────────────────────┐\n│  📋 SCOUTING REPORT                                  │\n│  ─────────────────────────────────────────────────  │\n│  Mission: Building codes for deck in Austin, TX     │\n│  Date: May 7, 2026                                  │\n│  Jurisdiction: Travis County, Texas                 │\n│                                                      │\n│  ✓ FINDINGS                                         │\n│  ───────────────────────────────────────────────── │\n│                                                      │\n│  📚 TradeScout Knowledge Base (Verified)            │\n│  • Deck permits required if height > 30\"           │\n│  • Deck permits required if area > 200 sq ft       │\n│  • Electrical work requires licensed electrician    │\n│                                                      │\n│  📍 Local Data (Travis County, TX)                 │\n│  • Austin requires electrical inspection for power  │\n│  • Permit office: Austin Building Services          │\n│  • Typical permit time: 5-7 business days          │\n│                                                      │\n│  🌐 Live Web Search (Current Market)               │\n│  • 2026 Texas Building Code: Railing height 42\"   │\n│  • Average deck cost: $5,000-$15,000               │\n│  • Material prices up 3% from last quarter         │\n│                                                      │\n│  ✓ SYNTHESIS                                        │\n│  ───────────────────────────────────────────────── │\n│  To build a deck in Austin:                        │\n│  1. Measure your deck (height, area)               │\n│  2. Contact Austin Building Services for permit    │\n│  3. Hire licensed contractor if needed             │\n│  4. Schedule inspections                           │\n│                                                      │\n│  📊 Confidence: HIGH (Verified + Local Data)      │\n│  ⚠️  Always verify with local building department  │\n│                                                      │\n│  [🔄 Scout Again] [📥 Save Report] [📤 Share]    │\n└──────────────────────────────────────────────────────┘\n```\n\n### 3. Source Attribution Badges\n\n**Each source should have a clear badge/indicator:**\n\n```\n📚 TradeScout Knowledge Base\n   - Color: Blue (#0066CC)\n   - Icon: Book\n   - Meaning: Verified, from our database\n   - Confidence: HIGH\n\n📍 Local Jurisdiction Data\n   - Color: Green (#00AA44)\n   - Icon: Map Pin\n   - Meaning: Regional rules, local data\n   - Confidence: HIGH\n\n🌐 Live Web Search\n   - Color: Orange (#FF9900)\n   - Icon: Globe\n   - Meaning: Current market, web sources\n   - Confidence: MEDIUM\n```\n\n### 4. Confidence Indicators\n\n**Show confidence level prominently:**\n\n```\nConfidence: HIGH ✓\n  All three sources aligned. Data is verified.\n  Action: Safe to proceed.\n\nConfidence: MEDIUM ⚠️\n  Some sources available, but gaps exist.\n  Action: Verify before major decisions.\n\nConfidence: LOW ⚠️⚠️\n  Limited data available.\n  Action: Contact local authority or expert.\n```\n\n### 5. Progress Indicators (Streaming)\n\n**While Scout is gathering intelligence, show progress:**\n\n```\n🔍 Scouting in progress...\n\n✓ Thinking (analyzing your request)\n✓ Searching (gathering from knowledge base)\n→ Searching (checking local jurisdiction data)\n  Searching (live web search)\n```\n\n### 6. Scouting Report Actions\n\n**Below each report, offer actions:**\n\n```\n[🔄 Scout Again] [📥 Save Report] [📤 Share] [❓ Clarify]\n```\n\n- **Scout Again**: Send a follow-up scouting mission\n- **Save Report**: Save to user's scouting history\n- **Share**: Share the report with others\n- **Clarify**: Ask Scout to expand on a specific finding\n\n---\n\n## Page Layout\n\n### Desktop Copy & Messaging\n\n### Scouting Request Examples\n\n**Instead of:**\n- \"Ask Scout a question\"\n- \"What do you want to know?\"\n\n**Use:**\n- \"Send Scout on a mission\"\n- \"What do you want to scout?\"\n- \"Scout for...\"\n\n### Report Messaging\n\n**Instead of:**\n- \"Here's my answer...\"\n- \"I found this information...\"\n\n**Use:**\n- \"Scout Report: Here's what I found...\"\n- \"Intelligence gathered from 3 sources...\"\n- \"Local data shows...\"\n- \"Our knowledge base indicates...\"\n\n### Empty State\n\n```\n┌──────────────────────────────────────────┐\n│  🔍 Ready to Scout                       │\n│                                          │\n│  Send Scout on a mission to find:        │\n│  • Building codes & permits              │\n│  • Material & labor pricing              │\n│  • Licensed contractors & trades         │\n│  • Local regulations & requirements      │\n│                                          │\n│  [Scout for building codes...]           │\n│                                          │\n└──────────────────────────────────────────┘\n```\n\n---\n\n## Color Scheme\n\n```\nPrimary (Scout Action): #0066CC (Blue)\nKnowledge Base: #0066CC (Blue)\nLocal Data: #00AA44 (Green)\nWeb Search: #FF9900 (Orange)\nSuccess/Verified: #00AA44 (Green)\nWarning/Limited: #FF9900 (Orange)\nError/Missing: #CC0000 (Red)\nNeutral: #666666 (Gray)\nBackground: #F5F5F5 (Light Gray)\n```\n\n---\n\n## Accessibility\n\n- **Semantic HTML**: Use `<article>` for reports, `<section>` for findings\n- **ARIA Labels**: \"Scouting Report\", \"Source: TradeScout Knowledge Base\"\n- **Keyboard Navigation**: All actions accessible via keyboard\n- **Color Contrast**: 4.5:1 minimum for text\n- **Focus States**: Clear focus indicators on all interactive elements\n- **Screen Reader**: Report structure is logical and scannable\n\n---\n\n## Key Principles\n\n1. **Active, Not Passive**: Scout gathers intelligence; it doesn't just answer\n2. **Multi-Source**: Always show where information comes from\n3. **Transparent**: Confidence levels and disclaimers are visible\n4. **Actionable**: Every report leads to clear next steps\n5. **Trust-Building**: Source attribution and verification badges build confidence\n6. **Mobile-First**: Works seamlessly on phones and tablets\n7. **Fast**: Streaming shows progress while gathering intelligence\n8. **Professional**: Scouting reports look authoritative, not chatty\n\n---\n\n## Implementation Checklist\n\n- [ ] Rename \"Message\" input to \"Scouting Request\"\n- [ ] Rename
